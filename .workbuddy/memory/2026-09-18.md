## 追加：切片在编辑器里「大片空白」的根因（用户贴 FA2 截图）

用户贴了一张 FA2 截图（切片在编辑器里打开），确认是**切片**。查清了根因，**不是数据丢失**：

### 根因：切片画布远大于它承载的地形块

- `MapFile.CreateEmptyMap(s,s)` 把**每一格**的 TileNum 初始化为 `Common._000_Empty`，
  而 **`Common._000_Empty = -1`**（实测）。没被 `putTile` 写到的格就停在 −1 上。
- 切片边长 `s` 由 topCorner 与 indicator 缝共同决定：TEMPERATE 时 `s = 19` ⇒ 画布 **703 格**；
  而真正承载的地形块只有 **15×15 = 225 格**（topCorner 13 → 局部 rx/ry ∈ [13,27]）。
- ⇒ 覆盖率上限 = 225/703 ≈ **32%**。实测全量 89 张切片：**最低 1% / 中位 33% / 最高 33%，
  89/89 张都 < 60%**。矩阵是在对角线方向逐层收缩的（网格中每一层是 14→33→16），
  **不是**边缘块特有现象，而是**每一张**都如此。

### 与手工地图单元的差异（这是「应该长什么样」的基准）

| 产物 | Size | −1 占比 | 0 占比 |
|---|---|---|---|
| 我们的切片（TEMPERATE） | 19×19 | **86~99%** | 5% |
| `MapUnits/TEMPERATE/001.map` 等 | 20×20 | 26% | 33% |
| `MapUnits/DESERT/*` `NEWURBAN/*` | 30×30 | **≈0%** | 5~14%（其余是真图块） |

⇒ 手工单元习惯是**把无内容的格填成 0（清地）**，几乎不留 −1；我们的切片把 68% 留在 −1。

### 已核实 / 未核实（不要越界下结论）

- 已核实：`CreateEmptyMap` 初值 = −1；s 的推导；全量覆盖率矩阵；手工单元的占比。
- 已核实：`workingMap.ts:270` 的 `TileNum !== 0 && TileNum !== -1` 是 **cannotplacesmudge** 的过滤，
  **不能**用来断言「0 与 −1 对单元等价」。
- **未核实**：`AbstractMapUnit.Initialize`（`tile/abstractMapUnit.ts:115-126`）**不过滤** 0/−1，
  把绝对 (Rx,Ry) 平移到单元局部网格后原值存入 `AbsTileType`；因此「切片未写格填 0 还是留 −1」
  对下游 stamp 是否等价，**尚未验证** —— 要改默认值前必须先验这一条。
- 已核实：`scripts/verify-split.mjs` 的「内容区图块与源一致」断言里
  （第 407-408 行）`if (!abs) continue;` **会跳过源图不存在的格**，
  所以它从未检查「块覆盖率」，这个盲区正是本次问题没被拦住的原因。

### 追加（同日稍后）：等价性验证完成，结论已定

用户选定「先验证 + 补断言」。已在 `scripts/verify-split.mjs` 末尾新增
「切片空白格语义（块外格惰性证明 + 覆盖率统计）」一节，`RESULT: pass=25 fail=0`。

**机器实验结论（不再靠读代码推断）：**

1. **块外 −1 是惰性的**：把内容块之外的 −1 全部改成 0，
   `AbstractMapUnit.Initialize` 产出的 `AbsTileType` 15×15 模型**逐格一致**。
   原因（代码 + 实验互证）：`AbstractMapUnit.Width/Height = WorkingMap.MapUnitWidth/Height`（15），
   `Initialize` 只按 `Rx=i+StartingX, Ry=j+StartingY` 查内容块那 225 格；
   `PlaceMapUnitToWorkingMap` 也只遍历这 15×15 ⇒ 画布其余 ~478 格**根本不被读**。
2. **块内 −1 不是惰性的**：把块内 −1 也改成 0，模型会变（断言证明测试有牙齿）。
3. **修正我此前的错误推断**：块内 −1 是**显式的 TileNum=-1 记录**（Initialize 后 null 格数=0），
   不是"缺格"。之前猜"缺格 → null"被实验否定 —— 所以「块内一格都不能动」这个结论反而更硬了。
4. 覆盖率每跑一次都不同（min 1~2% / max 33% / avg 23~24%），因为
   **`genResult` 由 `Math.random()` 生成、内容非确定** —— 对比两次运行的绝对数字没有意义。

**给未来的边界**：若要做「编辑器友好」的实心切片，唯一安全做法是
把 `buildSlice` 里 `CreateEmptyMap` 之后的**块外**格置 0（`Rx∉[SX,SX+W) 或 Ry∉[SY,SY+H)`），
块内原样保留；改完必须重跑本节断言（它们就是为这个场景准备的）。
另注：verify-split 的源图每次运行都不同，脚本里做跨运行数值对比没有意义。
